# HC22000 imports

The report reads local `.hc22000` files for inventory and interpretation. It does not transmit, recover credentials, verify MICs, or reconstruct missing captured packets.

## Import through the HTML page

1. Open the latest report and find **HC22000 files**.
2. Choose one or more exports from your computer. Nothing is uploaded.
3. Open **View imported records**. Search by network, AP/client address, source filename, or type; use the PMKID/EAPOL type filter.
4. Select **View** for record metadata or download **Filtered rows** / **All rows · CSV**.
5. Expand **Skipped records and import issues** for malformed-line explanations. At most 100 issue details are shown; the total invalid-line count is retained.

Browser additions stay in memory until the page is reloaded. **Clear browser imports** restores the records originally embedded by the CLI, preserving that generated report's baseline. To persist an import into HTML, use the CLI below. CSV downloads contain metadata, not reusable raw hash lines.

## Import from Terminal

Attach an export to the latest Kismet capture:

```sh
alfa-report --hc22000 "/path/to/export.hc22000" --open
```

Attach exports to a specific capture:

```sh
alfa-report "/path/to/session.kismet" \
  --hc22000 "/path/to/first.hc22000" \
  --hc22000 "/path/to/second.hc22000" --open
```

Create a standalone metadata report:

```sh
alfa-report "/path/to/export.hc22000" --open
```

Standalone imports do not require Kismet or its PCAP converter. They are saved under `~/Captures/ALFA/Imported reports/` (or the configured `ALFA_DATA_DIR`). If `--hc22000` is used with no existing Kismet capture and no positional capture argument, it also creates a standalone report.

Every successful generation updates **Latest Report**. `hc22000.csv` contains imported metadata; `hc22000-errors.csv` contains up to the first 100 malformed-line explanations. Originals are opened for reading and remain unchanged. New report runs do not automatically reimport previous files; repeat the arguments to include them.

## Interpret the record types

| Prefix | Display label | Meaning in this report |
| --- | --- | --- |
| `WPA*01` | PMKID | Exported PMKID metadata; no M1–M4 coverage implied |
| `WPA*02` | EAPOL | Embedded EAPOL-Key metadata and an exporter-supplied pair label |
| `WPA*03` | FT PMKID | PMKID metadata with FT identifiers |
| `WPA*04` | FT EAPOL | EAPOL metadata with FT identifiers |

EAPOL pair labels such as M1+M2 are decoded from the record's flags, not independently observed packets. A syntactically accepted file does not prove successful authentication, valid cryptography, or a complete four-message exchange. The HC22000 format does not provide packet timestamps or capture channels, so those fields are not invented.

The table includes the decoded SSID, AP/client MACs, pair flags, embedded EAPOL length, source filename/line, and a SHA-256 fingerprint for deduplication. Invalid UTF-8 SSID bytes are displayed with replacement characters. Raw PMKIDs, MICs, nonces, and EAPOL blobs are not included in the report metadata or CSV.

Input checks cover field count, hex encoding, lengths, FT identifiers, and the embedded EAPOL header/declared length. The metadata reader accepts EAPOL blobs up to 4,096 bytes; this is an import bound, not a guarantee of compatibility with a particular external tool. Exact records are normalized for hex case and empty/zero pair flags before deduplication. The first source filename/line is kept. Comments beginning with `#`, blank lines, and an initial UTF-8 BOM are tolerated.

The browser and Python parser share test vectors. Input limits are 10 MiB per file, 20 MiB per CLI invocation or browser selection, and 20,000 unique imported records. Raw exports are ignored by Git.

Format references: [Hashcat's format overview](https://hashcat.net/wiki/doku.php?id=cracking_wpawpa2#expected_file_format) and [its mode 22000 parser](https://github.com/hashcat/hashcat/blob/master/src/modules/module_22000.c).
